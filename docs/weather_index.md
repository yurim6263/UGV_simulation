# 기상 악영향 지표 (지도 표시 "기상")

지도의 위험도(`normalized_c_total` 등)는 지형과 날씨가 섞인 값이라 날씨만 따로 보이지 않는다. 위험도 31장의 분산을 나눠 보면
**칸마다 다른 고정분(지형 등)이 종합 92%, 기동성 95%, 센서 85%** 이고, 시간에 따라 변하는 몫(날씨)은 각각 8%, 5%, 15%뿐이다. 그래서 위험도 색만으로는 날씨가 잘 안 보인다.
이 지표는 원시 기상(ERA5-Land)에서 비, 안개 가능성, 토양수분, 바람을 하나(0~1)로 합쳐 지도 탭의 "기상"으로 보여 준다.

코드: `backend/app/weather/scenario_index.py`(계산), `backend/app/api/weather_map.py`(API), `frontend_js/src/replay/WeatherLegend.jsx`(범례).
테스트 `backend/app/tests/test_weather_index.py`. 자료 받기 `backend/scripts/download_era5_scenario.py`, 정합 점검 `backend/scripts/check_weather_alignment.py`.

## 지금 상태 (2026-10-29)

- 저장소의 월별 ERA5-Land는 2018-01 ~ 2022-12뿐이라 시나리오 날짜(2023-06-30 22:00~)가 없다. 그래서 `scripts/download_era5_scenario.py`로 **2023-06-29 ~ 07-01(UTC)을 받아** `backend/data/weather/era5_scenario.nc`에 두었다(72시간, 9x11칸, git 제외). 이 파일이 없으면 지표를 만들지 않고 화면에 "표시할 수 없음"과 이유를 알린다. 다른 해 같은 날짜의 값으로 대신하지 않는다.
- **날짜 확인은 끝나지 않았다.** 날짜 표기가 엇갈린다(위험도 지도 2023-06-30, 사례 폴더명 2023-07-26, 노트북 2024-07-03). 2023-06-30으로 받았고 다른 후보는 받지 않았다.
- `check_weather_alignment.py` 결과(31개 시각): UTC 오프셋 0 → 상관 0.38, +2시간 → 0.22. 약하다. 이유는 아래와 같다.
  - ERA5로 본 시나리오 구간(UTC 6/30 22시 ~ 7/1 03시)은 **비가 없고(0.00~0.04 mm/h) 안개 가능성도 낮은(최대 0.11) 잔잔한 밤**이다. 지표는 0.146 안팎에서 거의 변하지 않는다(토양수분 0.30 → 0.285가 가장 크게 변한다).
  - 위험도 종합 평균은 같은 구간에서 0.77 → 0.61로 계속 낮아진다. 이 변화는 이 ERA5 날씨로는 설명되지 않는다.
  - 같은 파일에서 6/30 13시(UTC)에 비가 가장 셌고(2.8 mm/h) 이후 약해졌다. 시나리오는 그 비가 그친 뒤의 구간이라, "비가 온 날의 저녁 이후"라는 점에서는 모순되지 않는다. 하지만 이것이 같은 날씨라는 증거는 아니다.
  - 결론: **이 ERA5가 위험도 지도가 만들어진 날씨와 같다고도, 다르다고도 말할 수 없다.** 지도의 "기상"은 시나리오 구간에서 옅고 거의 균일하게 보인다(지표 약 0.15).
- 시나리오 시각(표준 시간대 정보 없음)은 UTC로 간주한다. 현지 시각이면 `WEATHER_UTC_OFFSET_H=2`(폴란드 여름)로 바꾼다.

### 자료를 받아서 켜는 법

1. `pip install cdsapi`(requirements-analysis.txt에 있다), 본인의 Copernicus CDS 계정 키를 `~/.cdsapirc`에 둔다 (키는 저장소에 쓰지 않는다).
2. `cd backend && python scripts/download_era5_scenario.py --dates 2023-06-30 2023-07-01` (자정을 넘기므로 두 날, 앞날은 자동으로 추가). 파일은 `backend/data/weather/era5_scenario.nc`로 저장되고 git에는 올라가지 않는다(`.gitignore`).
3. `python scripts/check_weather_alignment.py`로 ERA5 지표의 시간 변화가 위험도 실황의 시간 변화와 같은 방향인지 본다. 후보 날짜가 여럿이면 `--out`으로 따로 받고 `--file`로 비교한다.
4. 서버를 다시 시작할 필요는 없다(파일 수정 시각이 바뀌면 다시 읽는다).

## 계산 (모두 가정값, 보정하지 않았다)

| 요인 | 입력(ERA5-Land) | 0~1로 바꾸는 기준 | 가중치 |
|---|---|---|---|
| 비 | `tp`(누적 → 시간당 mm/h, 기존 `era5.rain_rate_mm`) | 5 mm/h 이상이면 1 | 0.4 |
| 안개 가능성 | `t2m - d2m`(이슬점 차), `u10,v10`(풍속) | 이슬점 차 0K → 1, 3K 이상 → 0, 곱하기 풍속 4 m/s 이상이면 0 (약할수록 1) | 0.3 |
| 토양수분 | `swvl1` | 0.15 → 0, 0.45 → 1 | 0.2 |
| 바람 | `u10,v10` | 15 m/s 이상이면 1 | 0.1 |

지표 = 가중합. 시간(턴 10분)은 시간별 값을 선형 보간하고, 원래 0.1° 격자에서 요인을 계산한 뒤 작전 구역 격자(200m)로 선형 보간한다. ERA5-Land는 바다 칸이 비어 있어 가장 가까운 육지 값으로 채운다.

## 한계 (화면의 "?"에도 같은 내용이 있다)

- **측정값이 아니라 가정이 들어간 추정이다.** 가중치와 기준은 근거 없이 정했다. 위험도(`c_mob`, `c_sen`)와 같은 척도가 아니고, 위험도 계산에는 쓰이지 않는다(보기 전용).
- **안개/시정은 ERA5-Land에 없다.** 이슬점 차와 바람으로 추정한 규칙일 뿐이다.
- **거친 격자**: 0.1°는 약 11km x 6km라 작전 구역(약 20km)에 2~4칸이다. 지도의 부드러운 모양은 보간이고 세부 위치별 차이를 말해 주지 않는다. 화면 범례도 "거친 격자를 보간한 값"이라고 적는다.
- **지형의 영향 없음**(순수 기상). 위험도에서 날씨만 떼어낸 것도 아니다.
- **날짜와 시각이 맞는지 확인 전**: 위 "지금 상태" 참고. `check_weather_alignment.py`는 시간 변화의 방향만 비교하며(31개 시각, 한쪽으로 변하는 추세), 맞다는 증명이 아니다. 낮거나 음수면 날짜/시각 불일치를 의심한다.
- 예보(예보 탭)에는 쓰지 않는다. 예보 탭은 위험도 예보만 있다.
- 값이 약한 날씨(비 없음, 바람 약함)에서는 0~1 고정 척도에서 지표가 낮아 지도가 옅게 보인다. 척도를 늘려 보이게 하지 않았다 (절대 크기를 읽을 수 있게). 시간 변화 그래프만 세로를 0~0.5 이상으로 맞춘다.

## 화면 확인 상태

- 자료가 없을 때("표시할 수 없음")와 시나리오 날짜의 실제 ERA5(2023-06-29~07-01)가 있을 때의 화면을 모두 확인했다. 통제관(user1) 화면에서 지표 0.15, 비 0.0 mm/h, 안개 가능성 8%, 바람 3.7 m/s, 토양수분 0.30이 보였다.
- 그 전에는 실제 ERA5 2022년 값을 +365일 옮겨 라벨한 임시 대역 파일로 모양만 확인했다(저장소에 없음, 시나리오 날씨 아님).
- 시나리오 구간이 잔잔해서 오버레이는 옅고 거의 균일하다. 날씨가 위험도에 미치는 영향이 지도에서 뚜렷이 "보이는" 결과는 얻지 못했다.
