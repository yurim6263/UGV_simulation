# 위험도(LTWR) 데이터 직접 생성: 팀원 결과물을 이 저장소 안에서 재구현한 부분

프로젝트의 위험도 지도(LTWR)와 그 재료는 원래 팀원이 만든 **파일**로만 저장소에 있었고 생성 코드는 없었다 (결과보고서에는 구조의 뼈대만 있다).
"모든 코드가 이 저장소 안에 있어야 한다"는 목표로, 아래를 직접 구현했다. **재구현한 것은 팀 원본이 아니라 우리 정의/재현이다.** 같은 수치가 나온다고 주장하지 않고, 어디가 일치하고 어디가 우리 가정인지를 구분해 적는다.

| 구성요소 | 팀 원본 | 이 저장소 (직접 구현) | 원본과의 관계 |
|---|---|---|---|
| 정적 지형 격자(토지, 품질 마스크, 도로 거리) | 파일만 (`data/map_20km/static`) | `app/geo/static_grid.py`, `scripts/build_static_grid.py` | **역산해서 재현** (일치율 아래) |
| 기상 예측 모델 | 결과보고서의 ConvLSTM(Seq2Seq), 코드 없음(XGBoost 노트북만 있음) | `app/weather/convlstm.py`, `scripts/train_convlstm.py` | 구조만 같고 **세부는 우리가 정함** |
| 안개 확률 | 팀 노트북(`xgb_fogProb_1h_ahead.ipynb`) | `app/weather/fog.py` | **노트북 식을 그대로 옮김** |
| 위험도 LTWR 생성 | 파일만 | `app/weather/ltwr.py`, `scripts/build_ltwr_layers.py` | 구조(0.6:0.4)만 같고 **식과 기준값은 우리 가정** |
| 위험도 레이어(실황 31, 예보 54) | 2023-06-30 22시 사례 파일 | `data/map_20km_rebuilt/` (2022-08-20 22시 사례) | **다른 날씨, 다른 값** |

팀 원본 데이터는 그대로 두었다 (`data/map_20km`, 환경변수 `MAP20KM_DIR=map_20km`로 쓸 수 있다). 기본은 우리가 만든 `map_20km_rebuilt`다.

## 1. 정적 지형 격자: 팀 파일을 재현

격자는 EPSG:3035의 200m 정사각형 111 x 111이다 (셀 중심의 위경도가 원본과 1e-13도 이내로 같다). 기존 파일과 셀별로 대조했다 (`build_static_grid.py`가 출력):

| 항목 | 방법 | 원본과 일치 |
|---|---|---|
| 토지 코드 `lc_code` | ESA WorldCover 2021 10m를 셀마다 **nearest**로 뽑음 (최빈값, 평균, 쌍선형은 81% 이하였다) | **99.6%** |
| 품질 마스크 `mask_good` | WorldCover InputQuality 밴드 3(무효 Sentinel-2 관측 비율)이 50% 이하 | **99.9%** |
| 도로 유무/거리 | OSM highway 중 motorway, trunk, primary, secondary, tertiary, unclassified, residential(+link), living_street, service를 주행 가능 도로로 보고 셀 중심에서 가장 가까운 도로까지의 거리(최대 5000m), 50m 이하면 있음 | 유무 **99.6%**, 거리 평균 오차 **1.1m** (track, footway, path를 넣으면 틀렸다) |

일치하지 않는 부분과 한계:
- 도로는 2026-10에 내려받은 OSM이고 팀은 몇 달 전 것이라 조금 다르다 (위 99.6%의 나머지).
- **위험도 파일이 담던 10,048칸(경로 버퍼)의 정의는 역산하지 못했다.** 출발지-정찰지 직선 버퍼(최대 일치 82%)나 마스크 tif 팽창으로도 맞지 않았다. 그래서 새로 만든 위험도는 **전체 12,321칸**을 담는다 (엔진의 "데이터 없음 NaN" 처리는 그대로 두었다).
- 원자료(WorldCover 약 1GB, OSM JSON 약 100MB)는 저장소에 없다 (`WORLDCOVER_DIR`, 도로는 첫 실행에 Overpass에서 받아 `backend/data/osm/`에 캐시).

## 2. 기상 예측 ConvLSTM

자세한 설정과 시험 구간 결과는 [weather_convlstm.md](weather_convlstm.md). 요약: Seq2Seq ConvLSTM(은닉 32 x 2, 25만 파라미터, 잔차 구조), 지난 12시간 → 이후 1~3시간, 학습 2018~2021 / 검증 2022 상반기 / **시험 2022-07 이후**.
시험 구간에서 평균 오차(MAE)는 지속성보다 모든 변수와 예측 시간에서 뚜렷하게 낫지만, **강한 비(≥1 mm/h)의 탐지는 지속성보다 나쁘다.** 이 한계는 위험도 예보에도 그대로 들어간다.

## 3. 위험도(LTWR) 생성: 원본에서 확인한 것과 우리가 정한 것

원본의 기존 위험도 파일을 분석해서 확인한 것:
- `normalized_c_total = 0.6 × c_mob_prime + 0.4 × c_sen_prime` (오차 1e-16). 복합 악조건 보정(synergy)은 기동/센서 값 안에 들어 있다.
- 값은 0~1이고 칸마다 매끈하다 (이웃 칸 평균 차이 0.016, 전체 표준편차 0.196). 지형만으로 설명되는 분산은 17~20%라서 날씨가 지도의 주된 변화다.
- 팀 노트북의 강수 임계 구간: 0.5(경미), 2(중간), 5(강함, 소프트 회피, "5 mm/h에서 센서 성능 붕괴"), 8 mm/h(매우 강함, 하드 회피).

**우리가 정한 것 (관측으로 보정하지 않은 가정값, 원본과 다르다)**:
- 변수별 0~1 위험 곡선: 위 강수 임계를 기준점으로 한 단조 PCHIP (`app/weather/curves.py`). 토양수분(0.2에서 0, 0.4에서 0.6, 0.5에서 1)과 적설 기준점은 근거 없는 가정이다.
- 기동성 = 강수, 토양수분(연약지반), 적설의 noisy-OR. 센서 = 강수, 안개의 noisy-OR.
- 지형 보정: 토지 피복별 바탕 위험과 젖은 땅 민감도, 도로 50m 안이면 젖은 땅의 영향 반감.
- synergy: 강수 x 토양수분(기동), 강수 x 안개(센서)의 곱(0.15)을 더함.
- 수역은 엔진이 통행 불가로 막아서 지형 보정 없이 날씨 값만 둔다.
- 시간: 시간별 값을 10분 단위로 선형 보간한다. 팀은 "보수적 선형보간"이라 했으나 정의를 알 수 없어 보수화 없이 선형 보간만 했다.
- 공간: ERA5-Land(0.1°, 약 11km)를 200m로 쌍선형 보간. **보간은 정보를 늘리지 않으므로 세부 위치별 날씨 차이를 말해 주지 않는다.** 지도의 공간 모양은 지형 보정에서 나온다.

## 4. 새 시나리오: 2022-08-20 22:00 ~ 08-21 03:00 (UTC)

ERA5-Land 2018~2022에서 작전 구역 평균으로 5시간 구간을 검색해 골랐다. **비와 안개가 같이 있다가 비가 약해지는 구간**이고(비 평균 1.9, 최대 4.6 mm/h), 기존 시나리오처럼 22시에 시작한다. 시험 구간(2022-07 이후)이라 ConvLSTM의 학습·검증에 쓰이지 않았다.
후보 기록: 비+안개 2022-08-20 22시, 호우가 그치는 2022-07-01 19시(최대 6.5 mm/h), 비+안개 2022-08-16 19시, 안개만 2022-11-01 03시.

- 실황 31장(10분 간격): ERA5-Land 시간별 값에서 계산. 예보 54장: 발표 3회(22:00, 23:00, 00:00) x 18장(0~170분), 발표 시각은 실황, **이후 1~3시간은 ConvLSTM 예측**이다. 실제 미래값을 예보로 쓰지 않았다.
- 구역 평균 위험도: 종합 0.82 → 0.56, 기동성 0.70 → 0.31(비가 약해지며 뚜렷하게 내려감), 센서 1.00 → 0.93.
- **센서 위험은 거의 포화(1.0 근처)다.** 팀 안개 식은 이슬점 차 0.3℃, 풍속 1.6 m/s에서 확률이 약 1이 되고, 이 시나리오 밤은 실제로 그 조건이다. 팀 원본 데이터도 센서 위험이 포화 상태였다(중앙값 0.95). 그래서 센서 위험은 시간과 공간의 변화가 작다.
- 예보 오차 (`scripts/forecast_skill_report.py`, 위험도 레이어 수준): 종합 평균 skill 0.48(지속성보다 나은 리드타임 72%), 기동성 0.55(83%). **센서 skill은 −144로 나오지만 신뢰할 수 없다**: 실황 센서 위험이 거의 상수라 지속성 오차가 0에 가까워 비율이 폭발한다. 발표 시각이 3개뿐이고 같은 밤이라 일반화할 수 없다.
- 기상 악영향 지표(지도 표시 "기상", [weather_index.md](weather_index.md))도 같은 ERA5와 같은 곡선, 안개 식을 쓴다. 두 시계열의 시간 변화 상관 0.99는 **같은 ERA5에서 만들었으니 당연한 값**이고 독립적인 확인이 아니다. 이 구성으로 팀 원본 데이터에서 풀리지 않던 날짜 불일치 문제는 기본 시나리오에서 사라졌다.

## 5. 한계 (결과를 읽을 때)

- 새 위험도는 **우리 정의**라서 팀 결과보고서의 수치(성공률 54→97% 등)와 같지 않다. 팀 결과를 재현한 것이 아니다.
- 예보 레이어는 ConvLSTM의 시험 구간 평가가 말하는 정도만 정확하다 (강한 비 탐지는 지속성보다 나쁨).
- 날씨는 한 사례의 5시간이다. 위험도 곡선, 가중치, 지형 보정, synergy는 보정하지 않은 가정값이다.
- **NSGA-II로 정한 모드의 전술 성향(산개, 기상 민감도 등)은 팀 원본 위험도에서 찾은 값이다.** 새 위험도에서 다시 최적화하지 않았다. 편성 계산(제대별 대수)은 새 위험도로 다시 계산했다.
- 시뮬레이션 사고 확률, 개입 AP, 지형 계수는 이전과 같은 가정값이다.

```powershell
cd backend

python scripts/forecast_skill_report.py                                                           # 예보 오차 (어시스턴트 도구가 읽음)
python scripts/precompute_formation.py --workers 2                                                # 기본 목표 편성 저장본 (데이터셋이 키에 들어 있어 자동으로 구분됨)
```

처음부터 다시 만들 때의 순서: `build_static_grid.py` → `train_convlstm.py`(약 50분, CPU) → 위 명령들. 원자료 경로는 환경변수 `WEATHER_ERA5_DIR`, `WORLDCOVER_DIR`.
